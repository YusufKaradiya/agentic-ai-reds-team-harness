# Acceptance Criteria

## Functional

- [ ] Attack corpus can be loaded from configuration.
- [ ] Direct injection tests can be executed.
- [ ] Indirect injection tests can be executed.
- [ ] Tool authorization can be evaluated.
- [ ] Sensitive-data leakage can be detected.
- [ ] Security decisions are logged.
- [ ] Evaluation metrics are calculated.
- [ ] Baseline comparison is available.
- [ ] Residual-risk report is generated.

## Engineering

- [ ] Python project is modular.
- [ ] Configuration is separated from business logic.
- [ ] Automated tests exist.
- [ ] Dependencies are documented.
- [ ] Docker deployment works.
- [ ] No secrets are committed.

## Research

- [ ] Literature review completed.
- [ ] Baseline defined.
- [ ] Evaluation protocol documented.
- [ ] At least one robustness/failure experiment completed.
- [ ] Ablation or architecture comparison completed.
- [ ] Limitations documented.
- [ ] Reproducibility protocol documented.

## Security

- [ ] Synthetic data only.
- [ ] Mock tools only.
- [ ] Untrusted input treated as untrusted.
- [ ] Retrieved documents treated as untrusted.
- [ ] Tool access is policy controlled.
- [ ] Audit trail exists.
